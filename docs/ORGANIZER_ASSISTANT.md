# 卡片、主題與多群使用方式

2026-11-07：已依明確核准完成 006 COMMIT、應用帳號稽核與正式部署，卡片／主題／多群旗標皆已開啟，HTTPS 健康／就緒通過。原管理群保留；新群仍需管理者在 LINE 申請並確認，實際卡片與多群收錄驗收待完成。

## 新群加入方式

沿用同一個 KIKI 官方帳號、既定管理者與現有金鑰，不必建立另一個 bot，也不用把群組 ID 貼到聊天或環境設定。LINE 的「Allow bot to join group chats」需開啟；已邀請成功的群組不必再邀一次。

1. 管理者在新群從成員清單真正標記 KIKI，輸入「申請啟用本群：群組名稱」。
2. KIKI 從驗簽成功的事件取得群組識別，只保存這個啟用要求；此時一般文字仍不收錄。
3. 核對提案中的群組名稱、收錄範圍、既定管理者與共用額度，按「確認提案」；也可真正標記後輸入「確認 P提案代碼」。
4. 收到「群組設定已確認」後才開始保存該群新文字。可用「群組狀態」核對。

每群都只有既定的同一管理者能操作；其他成員的新文字可依啟用設定保存，但不能下管理指令。各群的原文、工作、主題與短期對話分開查詢，不提供跨群彙整。回覆會出現在下指令的群內，群內成員都看得到。

所有群共用每日 20 次已接受 AI 要求、至少 30 秒間隔；每次通常一或兩次模型呼叫，並非 20 次 API 呼叫。沿用精選來源預設 20 則／12,000 字元與 30 分鐘短期對話。狀態、確認、取消提案、清單、歷程、主題設定與卡片狀態操作不呼叫 AI。不增加 API 金鑰。

預設最多同時啟用 3 群，包含原管理群；上限受 `ASSISTANT_MAX_GROUPS` 控制。只在原管理群可查「群組清單」，避免在其他群顯示別群名稱；各群皆可查自己的「群組狀態」。群名是管理者填寫的識別標籤，路由仍依 LINE 驗證事件中的群組 ID。

「停用本群」會先提出提案，確認後停止新一般文字收錄與一般操作，保留舊資料。待處理要求會取消，生成中要求會在下一次模型呼叫及發布前核對啟用版本；網路請求已送出後無法撤回。停用後仍接收已保存訊息的收回／編輯事件以維護來源。重新啟用須再次申請並確認。不會補讀停用期間或 KIKI 開始收錄前的歷史。

已確認的啟用設定持續有效；收回當初申請訊息不等於停用。尚未確認的申請若來源被收回則無法套用。要停止收錄請明確使用「停用本群」並確認。

## 卡片按鈕

完整提案保留文字及可複製指令，再附確認／取消按鈕。工作清單可按「完成工作」先產生變更提案，確認後才更新正式狀態；「查看歷程」直接查詢。按鈕操作本身不使用 AI。

卡片綁定原群組、既定管理者、目標版本與有效時間。轉傳到其他群、其他人點擊、竄改或已過期的按鈕不執行；過期時重新查詢或使用文字指令。工作已更新時，舊完成按鈕會請你查最新清單。重複確認不會重複建立工作。

按鈕產生 LINE postback，另存在不可修改的操作紀錄，不會假造一則聊天訊息；工作來源同時區分文字與按鈕。無法收回的按鈕操作仍會重新核對其提案及原始文字來源。

採用 LINE Flex 訊息與 postback，保留桌面和手機可使用的文字替代方式，未採僅限手機的 Quick Reply。[LINE Flex 文件](https://developers.line.biz/en/docs/messaging-api/using-flex-messages/)、[postback actions](https://developers.line.biz/en/docs/messaging-api/actions/)、[群組功能](https://developers.line.biz/en/docs/messaging-api/group-chats/)。

## 長期主題關聯

例：「建立主題：教學測試；別名：課程籌備、教材準備」。核對提案並確認後，查教學測試也會搜尋兩個已確認別名，能找到較早且仍保存的相關文字。這是管理者明訂的關聯，不是自動將相似主題合併，也沒有新增向量服務或 embedding 費用。

- 「主題清單」：查看本群主題與代碼。
- 「主題 教學測試」或「主題 T代碼」：看關聯的已確認工作。
- 「主題別名 教學測試：課程籌備、教材準備」：提出完整替換別名清單；最多四個別名，確認後生效。
- 同一說法對到多個主題時，請使用完整名稱或 T 代碼指定，系統會要求釐清。
- 明確的 KIKI 合成主題碼和「再找更早的」沿用原查詢，不任意擴張主題。

新工作若明確使用已確認主題名稱／別名，預覽會列出關聯 T 代碼與版本，確認後才記錄關聯。既有工作可按完全相同的主題名稱／別名查詢，不批次改寫舊工作或聊天。來源改變、主題版本改變會阻止使用過時快取或套用舊提案。

主題定義來源已收回時，查找暫不沿用該主題。可先查代碼，再輸入「重建主題 T代碼：完整名稱；別名：新說法」重新提出完整定義；舊來源文字不會放入新預覽。這不會恢復因舊來源無效而失效的工作。

## 錯誤與使用邊界

回覆會區分要求辨識失敗、AI 未完成、提案版本變更、來源收回與主題歧義，提供可直接改用的指令。確認已寫入但 LINE 回覆失敗時不自動重寫；再次確認同一提案可安全核對，也可查工作清單／歷程。不可保證 LINE 發送失敗時還能在同一短期 token 上送出錯誤通知。

不執行寄信、外部行事曆或提醒排程。搜尋仍是資料庫中的字面主題、別名、日期及有限引用關係，可能漏掉未登記的不同說法；資料量大時仍可能觸及既有短逾時，不宣稱已驗證數月大量真實群聊。真正多人、多群 LINE 端到端與舊版 LINE 的實際呈現待上線驗收。
