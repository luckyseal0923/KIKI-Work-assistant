# KIKI 自然語言交辦

2026-11-06：自然語言功能已部署；一般問題、附文公告改寫、已保存文字的日期行程及精確主題歷史查找皆已實測。完整 62 項本機測試通過，驗收版本與未實測邊界見 [驗收紀錄](PHASE3_ACCEPTANCE.md)。正式環境已啟用，原始碼的 `ASSISTANT_FREEFORM_ENABLED` 預設仍為 false。

## 可以直接說什麼

仍由既定管理者本人，在原允許測試群輸入 `@` 並從成員清單選 KIKI，接著直接寫要求；不需要背指令。

| 類型 | 例子 | 讀取範圍 |
| --- | --- | --- |
| 自由提問 | 什麼是 SMART 目標？請用簡單例子說明。 | 本次要求，不讀群組歷史 |
| 文字草擬／改寫 | 把下面改成正式公告：明天下午兩點有合成測試課程，請準時參與。 | 本次附上的文字，不讀群組歷史 |
| 群組內容整理 | 把今天 OSCE 討論整理成會議紀錄，區分決議與待確認事項。 | 本群今天、目前仍保存且符合主題的限量文字 |
| 歷史查找 | 找出過去 OSCE 討論的決議；整理上週的群組訊息。 | 本群已保存歷史，可指定主題與訊息日期 |
| 文字行程查詢 | 11/10 我有什麼行程？ | 已保存文字內提到該行程日期的紀錄；不是連接外部行事曆 |

「幫助、狀態、今日摘要、今日待辦」保留為快捷方式；幫助會顯示新例子。

每次標記獨立處理。要修改上一份草稿，請附上要改的原文；本版不保存 AI 回覆作為後續對話記憶。歷史查找只涵蓋 KIKI 開始收錄後仍保存的文字，不能補讀加入前的 LINE 歷史、附件或其他群組。

「11/10 我有什麼行程」的 11/10 是文字內的行程日期；「整理 2026/11/05 的訊息」才是限制訊息貼出日期。支援昨天、前天、上週（週一至週日）、上個月、最近 1～366 天及一個日期或起訖日期；未指定年份的訊息日期以提出要求時的臺北年份解析。查找範圍會顯示在回覆中，歷史引用包含完整來源日期與時間。

明確主題代碼會由程式固定限制來源，避免模型遺漏代碼而讀取整天內容；一次請查一個代碼。其他主題採要求中的字面關鍵字。這是有限量的文字查找，尚未加入向量語意搜尋或完整行程資料表；換用不同詞彙、缺少年份、矛盾或未收錄的安排，仍需核對來源或補充。

可草擬信件與會議通知的文字，尚未接上真正寄信、排會議、修改其他系統、執行程式或即時網路查詢。知識回答不代表已完成即時查證；臨床、法律、財務等個別決策仍需實際資料與專業核對。

## 資料與費用範圍

- 每次要求含標記最多 8,000 個 UTF-16 單位。要求原文照既有收訊規則保存在 `linebot.messages`；工作表只增加標記結束的位置，不另複製要求、AI 輸入快照或回答。
- KIKI 先用一次小型 API 請求判斷用途；只有群組整理、歷史或文字行程查找才查詢群組資料。提問與附文改寫的兩個 API 階段都不附群組歷史。
- 群組資料以原允許群、目前未收回且符合範圍的訊息為限，最多選入最近 100 則，每則節錄至 2,000 個字元，全批最多 22,000 個 UTF-16 單位；超出會標示部分內容。
- 歷史查找不限制為今天；未指定訊息日期時，從已保存歷史搜尋至本次要求時間。最多讀出 101 筆候選以判斷是否超過 100 筆，不為顯示總數掃描並計算全部歷史。超過時顯示「至少 101 則」；這不是完整總筆數，也不保證全部歷史均已整理。
- 管理者自己的要求會傳給 OpenAI；群組整理另傳限量的 M 編號、時間、文字。程式不另傳群組 ID、成員 ID 或連線秘密。
- 一般提問、草稿、群組整理、原摘要與待辦共用每日最多 20 次 AI 要求及至少 30 秒間隔。自由要求通常有「分類＋回答」兩次 API 請求；澄清、能力說明或無來源時可能只有分類一次。每次接受的要求仍計一次額度，API 按實際使用量計費。
- 分類最多 500 輸出 token、回答最多 2,500；兩階段共用 20 秒 API 時間，工作總有效期仍 45 秒，不自動重試不確定是否已計費的請求。
- 輸出 `store:false`、不提供工具；這不是 OpenAI 零保留保證。其他群組成員看得到群內回覆。
- 發送前會核對管理者命令與選入來源是否修改／收回；命令取消或來源變動時停止發布。已發出的摘要、草稿與回覆不會隨日後原文收回自動刪除。

## 部署順序

1. 先部署新程式，保持 `ASSISTANT_ENABLED=true`、`ASSISTANT_FREEFORM_ENABLED=false`。四個快捷指令仍可在僅有遷移 003 的資料庫運作。
2. 以既有 `linebot` schema 擁有者（本環境 `supabase_admin`）執行 [004_freeform_assistant.sql](../migrations/004_freeform_assistant.sql)。僅為既有工作表增加 `request_offset`、擴充 kind CHECK、限制 offset 與新增一個預算索引；不增角色、ACL、登入或外部系統權限，保留原索引。
3. 在新容器臨時檢查，輸出只有設定是否齊全與資料庫權限結果：

   ```sh
   ASSISTANT_FREEFORM_ENABLED=true node scripts/check-assistant-config.js
   ASSISTANT_FREEFORM_ENABLED=true npm run db:check
   ```

4. 兩項通過後，在 Coolify Production 設 `ASSISTANT_FREEFORM_ENABLED=true`，Literal、Runtime 開啟、Build time 關閉，重新部署。既有 OpenAI 金鑰、LINE 權杖、管理者與群組不變。
5. 先用合成一般問題、附文公告草稿、主題整理、歷史查找及日期行程分別驗收，AI 要求之間至少隔 30 秒；核對輸出、工作狀態、來源範圍、引用及短期 token 清除。歷史擴充沿用 004 的表結構，不需新增角色、ACL、金鑰或 SQL 遷移。

停用自然語言交辦時，只把 `ASSISTANT_FREEFORM_ENABLED=false` 並重新部署；四個快捷指令繼續運作。停止所有 AI 回覆則先關此旗標，再關 `ASSISTANT_ENABLED`。保留資料表供查核，不刪原訊息、撤回紀錄或共享權限。

## 驗證與官方依據

62 項本機測試使用合成資料、PGlite 與模擬外部 HTTP。涵蓋真正標記、UTF-16 位置、003 相容與 004 重複套用、同一每日額度、不讀不必要歷史、兩階段時間與用量、引用檢查、去重、編輯／收回取消及憑證清除；歷史擴充另驗證舊日資料、日期格式、主題代碼、期間及 100 則上限。最新邊界修正也另通過 28 項相關測試。實際 API 與 LINE 結果另外記錄。

- [OpenAI Docs：Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)：使用受限分類與固定 JSON schema，並在應用程式再次驗證。
- [OpenAI Docs：文字生成](https://developers.openai.com/api/docs/guides/text)：沿用 Responses API，將固定指示與使用者輸入分開。
