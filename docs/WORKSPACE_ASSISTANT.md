# KIKI 接續對話與工作追蹤

2026-11-07：本版已正式部署並啟用，005 已 COMMIT，專用應用帳號稽核與 HTTPS 健康／就緒通過；初次實測發現單筆交辦負責人遺漏，已加保留明確指定者的修正，完整 87 項本機合成測試通過。真實 LINE 工作流程正在驗收，部署成功不代表所有情境已端到端通過。版本與證據見 [第四階段驗證](PHASE4_ACCEPTANCE.md)。

## 使用方式

沿用唯一允許測試群、既定管理者與真正的 LINE @KIKI。支援要求開頭的 ①／②、1. 等清單編號，不更動日期或原始存檔。明確的「新增待辦：…」等直接交辦由固定規則辨識，少一次 AI 分類；要求依群組討論或外部工具者仍另行分類。其他成員的普通文字可收錄，不能啟動管理操作。

| 想做的事 | 真正 @KIKI 後輸入 | 寫入正式工作？ |
| --- | --- | --- |
| 接續上一份答案 | 再短一點／改成條列式／那乙呢／是由誰負責／期限呢 | 否 |
| 查找更早的同主題 | 再找更早的 | 否 |
| 交辦工作 | 新增待辦：測試角色甲明天中午整理教材，主題 KIKI-WORK-01 | 先回完整提案 |
| 確認提案 | 確認 PXXXXXXXX（使用實際代碼） | 是 |
| 修改工作 | 把 WXXXXXXXX 標成完成 | 先回完整變更前後提案，再確認才更新 |
| 接續單筆工作 | 這件事完成了 | 前段須僅有一個目標；仍先提案 |
| 查詢進度 | 工作清單／明天有哪些待辦／查詢 KIKI-WORK-01 的已完成工作 | 清單與查詢不變更工作 |
| 看變更紀錄 | 工作歷程 WXXXXXXXX | 否 |
| 看或取消提案 | 待確認提案／取消提案 PXXXXXXXX | 取消待確認提案，不取消正式工作 |
| 重置短期記憶 | 重置對話 | 只清短期記憶 |
| 看用量 | 狀態 | 顯示 tokens 與模型費用估算 |

工作包含待辦、決議與行程。行程是 KIKI 內的文字工作紀錄，沒有寫入 Google／其他行事曆，也不會主動提醒或寄信。

## 每次問答如何選資料

1. 先辨識要求。獨立知識問答、附文改寫不讀群組歷史。
2. 工作查詢讀已確認紀錄的最新版本；歷史問題則在資料庫按本群、時間、主題／日期篩選。正式行程也可按正規化後日期查詢，已取消、已完成狀態不能被舊討論蓋過。
3. 歷史搜尋可補最多四個相關詞，依符合程度與時間排序。明確主題代碼強制精確篩選，不能擴大到別的代碼。
4. 只帶精選來源給模型。預設最多 20 則／筆、文字總長 12,000 字元；工作提案的既有工作內容與原始討論共用這個預算。有原始討論時，最多一半預算供既有工作候選，保留空間給討論。原始資料庫不因此截短。
5. 原始文字每則最多節錄 2,000 個字元；模型看到來源日期時間、M 編號、發言者代稱與選入範圍內的引用關係。回覆附引用、範圍及部分內容提示。
6. 「再找更早的」沿用前次可信查詢條件，往前次最早選入來源以前搜尋，不重送整段歷史，也會突破前一次的「今天」起點。需仍有有效短期上下文；若來源沒有保存或沒有相符詞，可能找不到。

候選文字查詢上限為 100 則，另用一則判斷是否還有更多；引用回覆最多向上／下追兩層，每層最多選四則子回覆，兩輪關聯資料庫查詢各有 101 則上限。最終仍受 20／12,000 限制。這是字面搜尋加相關詞與引用串接，尚未建置向量語意搜尋，不能保證找全所有同義說法或未引用的「我也可以」。

總長以 JavaScript UTF-16 長度計算；數值是來源文字預算，並非整個 API 請求 token 上限。固定提示詞、本次要求、結構欄位及短期前一答仍會另外占用 tokens。

## 短期上下文與真實發言者

保留最近一次成功送出的答案（最多 4,500 字元）、本段起始交辦與最近問句的指標、最多八輪已使用要求的指標、選入長度、查詢範圍及工作版本。連續追問保留待確認提案關聯；達八輪後不再延用，請重新指定原文。模型只收到有限的起始交辦、最近問句與前一答，不會收到八輪全部文字。只在判斷為追問時讀取；不是每次傳回全部聊天。有效期 30 分鐘，過期後由下一次工作輪詢清空快取內容；不刪原始群組訊息或正式工作。起始交辦與上一個要求重新載入文字時，各最多提供約 2,000 字元；30 分鐘以最近成功快取的更新計算。回答前會再次核對原始交辦與參與要求，收回後停止發布。

管理者代稱「管理者」，其他真實帳號以群組限定的 HMAC 代稱「成員＋代碼」辨識；不讀 LINE 顯示名稱、不送原始 User ID／Group ID 給模型。訊息正文仍可能包含人名，這不等於正文已去識別。單人假扮甲乙丙只驗證文字標籤理解，不能當成真實多帳號驗收。

若前次原文、引用來源、待確認提案或正式工作版本已失效，停止沿用舊快取，請重新指定主題。只有 LINE 已提供且本系統保存的引用原文才能串接，不能向 LINE 補抓未保存的舊訊息。

## 確認後才成為正式工作

- AI 一次產生 1～3 個動作，預覽含新增內容，更新則完整列出變更前後。預覽太長直接停止，不截去未看到的動作再讓人確認。
- 提案 10 分鐘到期。管理者必須真正 @KIKI 並輸入完整提案代碼；普通「好」或其他人的回覆不套用。
- 負責人、期限須有本次要求／引用／既有紀錄依據；缺少則留未指定。只有明說「由我負責」等文字才可把管理者或發言者代稱當負責人。
- 明天等相對日期按來源日期、臺北時區換算；更新狀態不重算原本的明天。月日缺年份會標示採用的來源年份；模糊週幾、錯誤日期或時間保留待確認，不猜日期。
- 套用時鎖定提案、來源狀態與目標版本，所有動作在同一交易完成。重複確認不重複套用；版本衝突、來源修改／收回、已取消、到期或完全相同工作會停止。
- 每次正式變更增加版本與一筆唯新增歷程。來源或確認訊息收回後，相關工作／歷程內容標為待重新確認，不再交給模型當有效事實；既有正式紀錄與歷程沒有自動刪除。
- 每筆工作來源鏈最多 101 則；長期反覆修改累積超出時會停止新提案，需要後續設計來源整理，不承諾無限更新。

若資料庫已套用，但 LINE 回覆失敗，不會自動反向改回已確認工作。可查工作清單／歷程或重送同一確認代碼，避免另建相同工作。

## 設定與部署

| 設定 | 預設 | 用途 |
| --- | --- | --- |
| ASSISTANT_WORKSPACE_ENABLED | false | 須同時啟用既有 assistant、freeform，且完成 005 |
| ASSISTANT_CONTEXT_MESSAGES | 20 | 可設 5～50，精選來源／工作筆數上限 |
| ASSISTANT_CONTEXT_CHARACTERS | 12000 | 可設 2000～22000，精選文字總長上限 |

部署順序：

1. 先部署程式，保持 `ASSISTANT_WORKSPACE_ENABLED=false`。原自由問答與收錄繼續使用舊表路徑；關閉旗標不讀寫新增表或用量欄位。
2. 檢視 [005 SQL](../migrations/005_workspace.sql)、[權限與復原說明](WORKSPACE_DATABASE_CHANGE.md)，由既有 schema 擁有者執行。不得使用共用 postgres 密碼填到應用。
3. 在新容器只為檢查暫設旗標，執行下列兩項；正式環境變數仍先維持關閉：

```sh
ASSISTANT_WORKSPACE_ENABLED=true node scripts/check-assistant-config.js
ASSISTANT_WORKSPACE_ENABLED=true npm run db:check
```

4. 兩項通過後設定 Production：`ASSISTANT_WORKSPACE_ENABLED=true`、來源上限 `20`／`12000`，Literal、Runtime 開啟，Buildtime 關閉，重新部署。既有金鑰、私網、角色登入與原群組沿用。
5. 核對部署版本、日誌、HTTPS 健康／就緒；再由管理者在原測試群以合成資料驗證，不把模擬 API 當成真實 LINE 驗收。

停用只需旗標 false 並重新部署。必要時再執行 [停用新 ACL SQL](../migrations/005_workspace_disable_acl.sql)，保留工作、原訊息及歷程，不動共享服務權限。詳見資料庫變更說明。

費用見 [用量控制說明](COST_CONTROL.md)，測試與尚未完成的真實驗收見 [第四階段驗證](PHASE4_ACCEPTANCE.md)。
